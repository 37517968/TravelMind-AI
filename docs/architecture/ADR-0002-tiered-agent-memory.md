# ADR-0002：按生命周期分层存储 Agent 记忆

- 状态：Accepted
- 日期：2026-09-19

## 背景

当前 `FileBasedChatMemory` 将对话消息保存到本机文件，无法安全支持多实例、统一过期和并发更新。聊天历史、模型上下文和长期用户偏好具有不同的访问方式与保留周期，不应存入同一个介质。

## 决策

- Redis：保存最近消息窗口、任务热状态和最新摘要缓存；
- MySQL：保存完整聊天历史、摘要版本、用户确认画像和审计事实；
- PGVector：保存经过筛选的长期语义记忆；
- Spring AI ChatMemory 只负责“本轮模型需要看到什么”，不承担完整聊天历史归档。

## 理由

- Redis 适合低延迟、TTL 和多实例共享；
- MySQL 适合可靠持久化、分页、权限和删除；
- PGVector 适合按语义召回少量相关长期记忆；
- 分层后可分别治理容量、隐私和生命周期。

## 后果

- 需要维护消息、摘要和语义记忆之间的派生关系；
- Redis 数据必须能够从 MySQL 重建；
- 长期记忆必须有写入门槛，不能向量化所有聊天内容。

## 复审条件

当单库数据量、跨地域部署或语义检索规模超过 PGVector 运维能力时复审。
