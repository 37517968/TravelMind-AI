# ADR-0003：使用 RabbitMQ 和 Outbox 执行可靠异步任务

- 状态：Accepted
- 日期：2026-09-19

## 背景

旅行规划包含大模型、RAG 和多个第三方工具，执行时间长且失败类型复杂。同步 HTTP 链路不利于削峰、恢复和多副本扩容。仅在数据库提交后直接发送消息又会产生“数据库成功但消息发送失败”的一致性窗口。

## 决策

- HTTP 接口先在本地事务中写入任务和 Outbox 事件；
- Outbox Publisher 将事件可靠发布到 RabbitMQ；
- Worker 使用手动 ACK、幂等键和持久化检查点执行任务；
- 关键队列使用 Quorum Queue；
- 可重试异常进入延迟重试队列，不可重试异常进入 DLQ；
- 不使用 Seata 包裹长时间的大模型和第三方调用。

## 理由

- RabbitMQ 适合任务队列、路由、确认、重试和死信；
- Outbox 将“业务状态”和“待发布事件”放在同一本地事务中；
- 至少一次投递配合幂等消费比跨系统长事务更可控。

## 后果

- 消费者必须能处理重复消息；
- 需要监控 Outbox 积压、消息积压和 DLQ；
- 最终一致性意味着索引或通知可能短暂延迟。

## 复审条件

当消息吞吐、保留时间或事件流分析需求显著超过任务队列模型时，评估 Kafka/RocketMQ。
