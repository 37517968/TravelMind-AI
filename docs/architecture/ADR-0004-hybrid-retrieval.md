# ADR-0004：使用 Elasticsearch 与 PGVector 混合检索

- 状态：Accepted
- 日期：2026-09-19

## 背景

旅行查询同时包含精确地名、景点名、日期等关键词，以及“适合带孩子、节奏轻松”等语义意图。单独使用关键词或向量检索都容易漏召回。当前 JVM 内 BM25 索引也无法支持可靠的多实例部署。

## 决策

- MySQL 作为社区内容和知识实体的事实源；
- Elasticsearch 负责 BM25、中文全文搜索、过滤与聚合；
- PGVector 负责语义向量召回；
- 第一版使用 RRF 融合两路排名；
- 通过 Outbox + RabbitMQ 同步两个派生索引，并支持对账和重建。

## 理由

- BM25 对地名和精确词匹配可解释；
- 向量检索对口语和隐含意图召回更好；
- RRF 按排名融合，不需要直接比较不同量纲的原始分数；
- 保留现有 PGVector 投资，同时把 JVM 内索引迁移到可共享服务。

## 后果

- 需要处理两套索引的最终一致性；
- 必须建立离线评测集证明混合检索优于单路基线；
- 数据量较小时运维成本高于单一检索引擎。

## 复审条件

当 Elasticsearch 单库向量检索能够以更低成本满足质量、过滤和规模要求时，评估索引合并。
