# 旅行预算计算 Skill

## 概述

此 Skill 负责根据旅行行程规划，计算详细的旅行预算。通过调用路线规划工具计算交通费用，通过网页搜索查询实时价格，结合知识库中的预算经验，生成准确的预算明细。

## 前置条件

**必需**：
- 已执行 `travel-itinerary-planning` 技能
- 上下文中包含 `destination`、`days`、`itinerary` 信息

**可选**：
- 上下文中包含 `travelers` 信息（默认2人）

## 参数定义

### 从上下文获取的参数（必需）
- `destination` (string): 目的地城市
- `days` (integer): 旅行天数
- `itinerary` (string): 行程规划内容

### 从上下文获取的参数（可选）
- `travelers` (integer): 出行人数，默认 2
- `travel_type` (string): 旅行类型，默认"舒适型"

## 工作流程

### 步骤 1：验证前置条件
```
检查上下文中是否包含：
- destination
- days
- itinerary

如果缺少，返回错误：
"请先规划行程，再计算预算"
```

### 步骤 2：计算交通费用

#### 2.1 市内交通
```
调用 route-planning-tool
根据行程中的景点计算每日交通距离
估算交通费用：
- 公交/地铁：约 50-80 元/天
- 出租车/网约车：约 100-150 元/天
```

#### 2.2 往返交通
```
根据目的地估算往返交通费用：
- 一线城市（北上广深）：1000-1500 元/人
- 热门旅游城市（三亚、云南）：1500-2500 元/人
- 其他城市：800-1200 元/人
```

### 步骤 3：计算住宿费用

```
调用 web-search-tool
搜索查询："{destination} 酒店 价格"

根据搜索结果和城市等级估算：
- 一线城市：300-500 元/晚
- 新一线城市：250-400 元/晚
- 其他城市：200-300 元/晚

计算公式：
住宿费用 = 价格/晚 × 天数 × 房间数
房间数 = (travelers + 1) / 2
```

### 步骤 4：计算景点门票费用

```
调用 web-search-tool
搜索查询："{destination} 景点 门票价格"

从行程中提取景点列表
为每个景点查询门票价格
如果查询失败，使用默认值：80 元/人/景点

计算公式：
门票费用 = Σ(景点门票) × travelers
```

### 步骤 5：计算餐饮费用

```
根据城市等级和旅行类型估算：
- 一线城市：150-250 元/人/天
- 新一线城市：120-200 元/人/天
- 其他城市：100-150 元/人/天

计算公式：
餐饮费用 = 价格/人/天 × days × travelers
```

### 步骤 6：计算其他费用

```
其他费用 = (交通 + 住宿 + 门票 + 餐饮) × 10%
包括：购物、小费、应急等
```

### 步骤 7：生成省钱建议

```
使用大模型生成个性化的省钱建议：
- 提前预订优惠
- 错峰出行
- 联票优惠
- 当地特色小吃
- 公共交通
```

## 输出格式

返回 Markdown 格式的预算明细：

```markdown
【{destination} {days}天旅行预算详细计算】
出行人数：{travelers}人

🚗 交通费用：{transport_cost} 元
  - 市内交通：{local_transport} 元
  - 往返交通：{round_trip} 元

🏨 住宿费用：{accommodation_cost} 元
  - 约 {price_per_night} 元/晚 × {days} 晚

🎫 景点门票：{attraction_cost} 元
  - {attraction1}：{price1} 元
  - {attraction2}：{price2} 元
  - ...

🍜 餐饮费用：{meal_cost} 元
  - 约 {price_per_day} 元/人/天 × {days} 天 × {travelers} 人

  - 购物、小费、应急等（约10%）

━━━━━━━━━━━━━━━━━━━━

📊 日均费用：{per_day_cost} 元/人/天

{saving_tips}
```

## 最佳实践

### 1. 价格查询策略
- 优先使用网页搜索获取实时价格
- 如果搜索失败，使用知识库中的历史价格
- 最后使用默认估算值

### 2. 准确性提升
- 根据季节调整价格（旺季 +30%，淡季 -20%）
- 根据节假日调整价格（节假日 +50%）
- 考虑提前预订的折扣（-20%）

### 3. 用户体验
- 提供详细的费用明细
- 标注价格来源（实时查询/历史数据/估算）
- 给出合理的价格区间

### 4. 性能优化
- 并行查询多个价格
- 缓存常用城市的价格数据
- 限制网页搜索的次数

## 示例

### 示例 1：基础预算计算

**上下文**：
```json
{
  "destination": "上海",
  "days": 3,
  "travelers": 2,
  "itinerary": "第一天：外滩→南京路→豫园..."
}
```

**执行流程**：
1. 验证前置条件 → 通过
2. 计算交通费用 → 市内 240元 + 往返 2400元 = 2640元
3. 计算住宿费用 → 400元/晚 × 3晚 = 1200元
4. 计算门票费用 → 搜索查询 → 960元
5. 计算餐饮费用 → 200元/人/天 × 3天 × 2人 = 1200元
6. 计算其他费用 → 600元
7. 生成省钱建议 → 使用大模型生成

**输出**：
```
【上海 3天旅行预算详细计算】
...
💵 预计总费用：6,600 元
👥 人均费用：3,300 元
```

### 示例 2：带实时价格查询

**上下文**：
```json
{
  "destination": "北京",
  "days": 5,
  "travelers": 2,
  "itinerary": "第一天：天安门→故宫..."
}
```

**执行流程**：
1. 搜索"北京 酒店 价格" → 找到平均价格 350元/晚
2. 搜索"故宫 门票价格" → 60元/人
3. 搜索"长城 门票价格" → 40元/人
4. 综合计算 → 总费用 8,500元

## 故障排查

### 问题 1：缺少行程信息

**症状**：上下文中没有 itinerary

**解决方案**：
```
返回错误信息：
"请先规划行程，再计算预算。
您可以说：帮我规划{destination}旅游"
```

### 问题 2：价格查询失败

**症状**：web-search-tool 返回错误或无结果

**解决方案**：
1. 使用知识库中的历史价格
2. 使用默认估算值
3. 在输出中标注"价格为估算值"

### 问题 3：价格异常

**症状**：查询到的价格明显不合理

**解决方案**：
1. 验证价格范围（如酒店 50-5000元/晚）
2. 如果超出范围，使用默认值
3. 记录异常日志

## 注意事项

1. **依赖检查**：始终检查是否有行程信息
2. **价格来源**：标注价格是实时查询还是估算
3. **误差范围**：提示用户实际费用可能有 ±20% 的误差
4. **季节因素**：考虑旺季和淡季的价格差异
5. **汇率问题**：如果涉及境外旅游，需要考虑汇率
